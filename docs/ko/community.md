## 처음 이슈를 열 때

가능하면 다음 정보를 함께 포함해 주십시오.

- Node, 브라우저, Rust 중 어떤 표면에서 문제가 났는지
- 입력 Markdown 또는 fixture 입력
- 기대한 문서 결과
- 실제 결과
- 사용한 버전과 실행 환경

문서화된 안정 계약과 실제 동작이 다르면 버그 이슈가 맞습니다.
새 출력 기능이나 더 넓은 HWPX 범위가 필요하다면 기능 요청으로 분류하는 편이 적절합니다.

## 처음 PR을 보낼 때

작고 목적이 분명한 변경을 권장합니다.

- 한 PR에는 한 가지 목적만 넣기
- 출력 동작이 바뀌면 fixture 또는 smoke test 근거 포함하기
- 관련 문서도 함께 맞추기
- 전체 테스트를 green 상태로 유지하기

이 프로젝트는 문서 생성 결과를 중요한 계약으로 보기 때문에, 코드 설명만큼 실제 산출물 검증이 중요합니다.

## HWPX에 기여할 때

HWPX는 현재 베타 계약입니다.

- 승인된 fixture 기준 안의 동작인지 먼저 확인합니다.
- XML만 보지 말고 실제 문서 결과를 함께 검토합니다.
- 필요하면 `open` 명령으로 생성 결과와 golden 산출물을 적극적으로 비교합니다.
- 공식 문서보다 실제 호환 동작이 더 중요할 수 있으므로, 관찰 결과를 근거와 함께 남겨 주십시오.

## 한국어 사용자 관점의 추천 경로

1. 처음 도입할 때는 npm DOCX부터 시작합니다.
2. 브라우저 제품이라면 브라우저 DOCX 예제로 통합 가능성을 먼저 확인합니다.
3. HWPX가 꼭 필요할 때만 베타 계약을 이해한 뒤 좁은 범위에서 검증합니다.
4. 문제가 생기면 작은 재현 입력과 함께 이슈를 엽니다.
