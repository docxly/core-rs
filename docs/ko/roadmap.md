# 로드맵

이 로드맵은 방향을 설명합니다. 특정 릴리스 날짜를 약속하는 문서는 아닙니다.

## 현재 초점

`docxly`는 애플리케이션 안에 내장되는 문서 생성 엔진으로서의 채택을 우선합니다.

즉, 다음에 집중합니다.

- Node와 브라우저에서 좋은 DOCX 경험
- HWPX 성숙도에 대한 명확한 계약
- 결정적인 출력과 신뢰할 수 있는 회귀 게이트
- 작고 방어 가능한 공개 API

## 단기 우선순위

1. 제품형 예제 확장
   서비스 측 export, 브라우저 다운로드, 한국어 문서 워크플로 같은 실제 통합 예제를 보강합니다.
2. HWPX 성숙도 명확화
   검증된 fixture를 provisional에서 approved로 승격하고, 더 넓은 표 범위와 향후 이미지 지원을 포함해 그 의미를 사용자 문서에 명확히 적습니다.
3. 기여자 온보딩 개선
   외부 기여자가 프로젝트 규칙을 추측하지 않고도 작은 변경을 보낼 수 있게 이슈/PR 흐름을 명확히 합니다.
4. 패키징 전략 정리
   Rust crate를 정식 배포 흐름에 포함할지, 수요가 확인될 때까지 workspace-first로 둘지 판단합니다.
5. 실제 도입 사례 기반 우선순위화
   가상의 완성도보다 실제 통합 마찰에서 나온 피드백을 우선합니다.

## 현재 목표 범위 밖

- 범용 문서 변환 도구가 되는 것
- Pandoc의 모든 출력 및 템플릿 워크플로를 그대로 따라가는 것
- 내부 모듈을 넓은 확장 표면으로 공개하는 것
- fixture와 검증 없이 HWPX 전면 호환을 주장하는 것

## 의사결정 기준

다음에 가까운 변경은 더 잘 받아들여집니다.

- 애플리케이션 팀의 채택을 직접 돕는 변경
- 결정적인 출력 보장을 유지하는 변경
- 새 동작에 대한 테스트나 fixture를 함께 추가하는 변경
- 공개 계약을 좁고 명확하게 유지하는 변경

다음에 가까운 변경은 우선순위가 낮습니다.

- 명확한 수요 없이 API 표면만 넓히는 변경
- 검증이 약한 포맷 동작을 추가하는 변경
- 실제 출하 신뢰성보다 추상화를 우선하는 변경
